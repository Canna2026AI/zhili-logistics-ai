# 智立科技物流AI系统产品规格

## 1. 产品目标

系统把客户下单、渠道报价、仓库作业、干线转运、轨迹异常、应收应付、客户协同、设备扫描和外部连接串成可审计闭环。它不是运单 CRUD，也不承担通用总账；所有关键业务以领域命令、状态机、权限、审计和财务不变量实现。

成功标准：同一业务数据在运营端、客户门户、PDA、开放 API 和自动化中保持一致；每个功能都有真实持久化、权限负例、异常态、审计记录和自动测试。

## 2. 用户与数据边界

| 用户 | 主要任务 | 默认数据范围 |
| --- | --- | --- |
| SaaS 平台管理员 | 租户、模块、配额、公告、代入 | 平台级；代入必须限时审计 |
| 租户管理员 | 组织、角色、参数、模板、接口 | 当前租户全部 |
| 销售 | 客户、查价、报价、下单 | 本人及所属组织客户 |
| 操作/客服 | 订单、轨迹、异常、资料补录 | 指定站点、部门或客户 |
| 仓库员/PDA | 收货、测量、分货、装载、出库 | 绑定仓库与任务 |
| 财务 | 应收、应付、账单、收付、核销 | 指定公司、部门和账套范围 |
| 经理 | 业务量、服务质量、利润、现金 | 授权组织范围 |
| 客户管理员 | 客户账号、联系人、所有本客户业务 | 当前客户全部 |
| 客户联系人 | 下单、轨迹、账单、工单 | 自己或授权业务 |
| API 客户端 | 批量交换业务数据 | 租户、客户与作用域约束 |

权限统一建模为 `Tenant + Subject + Resource + Action + DataScope + FieldPolicy`。前端隐藏不是权限，所有命令必须在后端再次鉴权。

## 3. 核心业务闭环

1. 维护客户、代理、渠道、分区、费用、汇率、仓库和权限。
2. 客户或员工录入/导入标准、FBA 或平台订单，系统完成地址、品名、限制和报价校验。
3. 保存报价版本、逐项费用、利润、舍入方式和选择原因；预报进入待收货。
4. 仓库扫码匹配预报，记录实重、材积、图片、差异和异常；扫码以设备事件幂等。
5. 自动或人工分配渠道，生成订舱、提单、袋/托/柜和出仓任务。
6. 自营或合作尾程接货后生成派送任务，扫描打托、派送、签收与 POD 回传进入统一事件流。
7. 承运商与人工轨迹进入统一事件流，异常工单与运输主状态并行存在。
8. 费用规则生成应收应付，财务审核后形成冻结快照、账单与对账单。
9. 收付款支持部分金额、多币种和未分配余额；核销、冲销、调整与利润保持可追溯。
10. 客户门户、通知、Webhook 和报表读取相同领域结果，不复制业务逻辑。

## 4. 运单与异常状态

主状态：草稿、已预报、待收货、已收货、待分货、待转运、转运中、派送中、已签收、待退件、已退件、已取消。

异常不覆盖主状态，单独以工单表示：收货差异、资料缺失、渠道限制、扣货、轨迹停滞、破损、丢失、退件、索赔和费用争议。状态命令记录操作者、来源端、前后状态、原因、幂等键、关联任务及副作用。

## 5. 尾程与合作尾程

尾程不是承运商轨迹的别名，而是 v1 的完整运营域。系统支持自营站点和合作方两种模式，并以相同命令与审计模型处理接货、派送和签收。

- 接货批次把干线到货、合作方清单和实物扫描对齐，差异生成工单而不静默改数。
- 派送任务绑定站点、路线、司机或合作方、袋/托、计划时间窗和运单集合。
- PDA 支持接货、打托、装车、派送、异常和签收扫描；签收可采集姓名、时间、位置、照片和签名。
- POD 是不可变签收证据版本；补录与更正保留旧版本、原因、权限和审计。
- 合作方同步使用外部 ID 映射、幂等事件、状态对账、死信和人工重放。
- 尾程应收应付、司机/合作方费用和 POD 附件进入同一物流结算闭环。

## 6. 报价不变量

- 报价输入包含客户、渠道、起止地、邮编、重量、体积、件数、品名、日期和币种。
- 计费重、分区、重量段、基础价、燃油、偏远、超长、操作费、报关费、税费、客户特殊价和利润规则逐项可解释。
- 历史运单绑定报价快照，不随价卡编辑而变化。
- 优先级、边界重量、进位、最低消费、币种换算和舍入必须有确定规则与测试。

## 7. 财务与客户资金不变量

- 已审核费用不能直接覆盖，只能反审核、冲销或调整。
- 账单已发送后重新生成必须创建新版本或差异调整。
- 收付款总额等于已分配金额加未分配余额。
- 费用分摊前后同币种总额守恒，跨币种同时记录原币、汇率和本位币。
- 已核销账单不得删除；期间关闭后仅允许授权调整单。
- 扣货和信用策略在出仓命令中强校验，放货要求权限、原因和审计。
- 客户“账户余额”只表示物流结算预存款和未分配收款，不是通用消费钱包，也不允许租户间转账。
- 充值或账单支付必须先创建支付订单；微信支付回调按平台单号和微信单号双重幂等入账。
- 支付成功、关闭、失败、退款和部分退款均写资金流水；退款不得超过原支付可退余额。
- 支付分配、撤销分配和退款后，支付总额、已分配、未分配与退款金额满足守恒。

## 8. AI 自动化边界

AI 网关支持 OpenAI 默认适配器，并预留火山、通义和 DeepSeek。模型可按租户策略自动完成分类、分派、字段补全、通知草稿、Excel 映射和低风险状态推进。

金额、审核、核销、扣货/放货、删除和敏感导出必须人工确认。每次 AI 动作记录模型、提示版本、授权主体、输入摘要、策略命中、工具调用、输出和回滚信息。

## 9. 外部与上线边界

- 首批重点连接器：UPS、DHL、Amazon SP-API、企业微信、微信支付。
- 没有生产凭据时，以官方沙箱或高保真契约沙箱通过为完成标准。
- 只使用微信官方能力，不实现个人微信自动化。
- 发票实现抬头、税号、税率、申请、审批、红冲状态、附件和账单关联；不直接开具数电票。
- 首版交付 GitHub、GHCR 和 Docker Compose，不包含真实公网生产部署与 Kubernetes。
- 连接器范围：UPS、DHL、Amazon SP-API、企业微信和微信支付为 P0；Temu、TikTok Shop、SHEIN 为 P1；保险、微信公众号通知和经合法授权的 T6 数据迁移桥为 P2。个人微信自动化、绕过平台授权和未授权 T6 接口明确排除。
- 首版支持中文和英文界面，存储 UTC 与来源时区；日期、数字、币种、重量和尺寸按租户 locale 显式格式化。
- 数据迁移包含全量导入、增量追平、抽样/总量校验、冻结窗口和可回滚切换，不直接读取未授权竞品数据库。
- 打印通过浏览器打印和可选本地打印代理完成，打印任务、重打原因和副作用幂等均可审计。
