# v1 范围与边界决策

本页把竞品研究中出现、但容易在实现阶段静默消失的能力明确标为 `P0`、`P1`、`P2` 或 `OUT`。优先级改变必须更新功能追踪、页面矩阵、OpenAPI 和验收证据。

| 能力 | 决策 | v1 行为与边界 |
| --- | --- | --- |
| 自营尾程 | P0 | 接货批次、派送任务、路线/司机、打托装车、派送、异常、签收和 POD |
| 合作尾程 | P0 | 合作方、外部 ID、任务下发、状态/POD 回传、对账、死信和人工重放 |
| 客户资金账户 | P0 | 仅物流结算预存款与未分配收款，不是通用钱包，不支持跨租户转账 |
| 微信支付 | P0 | 预存款充值、账单支付、回调、关闭、退款、对账和财务入账 |
| UPS / DHL | P0 | 查价、下单、面单、轨迹、取消和状态对账；无生产密钥以官方沙箱验收 |
| Amazon SP-API | P0 | 授权、FBA 订单/货件同步、限流、重试和状态对账 |
| 企业微信 | P0 | 官方应用通知和 OAuth/身份映射，不使用个人微信自动化 |
| Temu / TikTok Shop / SHEIN | P1 | 预留连接器端口、凭据和映射模型，v1.1 实现官方授权能力 |
| 保险 | P2 | 投保申请、保单号、保费和理赔关联；不自建保险产品 |
| 微信公众号通知 | P2 | 仅官方模板消息和用户授权范围 |
| T6 数据迁移桥 | P2 | 仅经客户合法授权的导出文件/API；不逆向专有接口或读取未授权数据库 |
| 通用总账/税务开票 | OUT | 仅物流业务结算和发票申请/记录，不直接开具数电票、不替代会计总账 |
| 个人微信机器人 | OUT | 不实现个人号自动化、消息抓取或绕过微信官方能力 |
| Kubernetes 公网生产部署 | OUT | v1 提供 Docker Compose、GHCR 与部署文档，不代替客户生产变更审批 |

## 支付业务定义

“充值”在 UI 和 API 中统一称为“增加预存款”。支付成功后生成不可变资金流水，并进入客户未分配余额；客户可将余额分配到账单。直接账单支付则在回调成功后按支付订单中冻结的分配意图核销，失败时不改账单。

支付订单状态为 `CREATED → PENDING → SUCCEEDED`，也可从 `CREATED/PENDING` 进入 `CLOSED/FAILED`。成功后可进入 `PARTIALLY_REFUNDED/REFUNDED`。任何回调乱序或重复不得重复入账；金额、币种和商户号不匹配时隔离为人工对账异常。

## 迁移与切换定义

迁移采用来源盘点、字段映射、全量演练、增量追平、总量与金额校验、业务冻结、最终增量、切换和回滚观察窗。每个批次保存来源指纹、转换版本、错误报告和回滚边界。历史审计若无法可信迁移，必须标记来源系统与可信度，不伪造本系统操作者。

## 许可证与公开承诺

仓库源代码计划使用 AGPL-3.0；第三方依赖必须通过许可证扫描。官网只有在仓库 LICENSE、NOTICE、依赖报告和商业授权策略均经负责人确认后，才公开“开源”承诺。法律页使用运行时年份，并保存版本、发布日期和 owner。
