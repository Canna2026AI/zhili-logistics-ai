# 智立科技物流 AI 系统：B1 持久化对齐实现报告

日期：2026-07-22
范围：identity、rates/orders/waybills、warehouse/linehaul/last-mile 三份 P0 审计中的共享 PostgreSQL 缺口。

## 结论

已用 `0002_b1_persistence_alignment` 将三份审计中的 P0 请求字段、业务聚合、幂等上下文和认证能力补入真实 PostgreSQL 模型。实现包含 Drizzle schema、顺序 up migration、显式 0002-only down、快照、RLS/FK/约束和行为级 Testcontainers 测试；不是内存占位或只写 JSON 的影子实现。

迁移已验证：

- 现有 `0000 -> 0001` 数据库可升级到 `0002`；
- `0000 -> 0001 -> 0002 -> down 0002 -> down 0001 -> up` 的 schema fingerprint 完全一致；
- R2 legacy foundation 可顺序升级，且不会改写预先存在的角色、owner 或 `btree_gist` 依赖；
- 从 foundation 快照生成完整 Drizzle schema 可安装到 PostgreSQL 17；
- 所有 tenant 表启用并强制 RLS，新增业务 FK 使用复合 tenant ownership。

## 新增持久化聚合

### 身份、组织与平台控制面

- `user_organization_memberships`：用户多组织归属及单一主组织；
- `partner_contacts`：伙伴联系人规范化存储，支持单一主联系人；
- `reauthentication_grants`：再认证授权摘要、session、action classes、过期/消费/撤销生命周期；
- `login_throttle_buckets`：跨实例共享的登录失败窗口和封禁状态；
- `auth_resolve_tenant(text)`、`auth_lookup_oauth_state(text)`：WeChat pre-tenant 阶段只返回 active tenant 或固定 dummy，OAuth state 仍须进入 tenant RLS transaction 后原子 consume；
- `control_plane_create_tenant(...)`：替换旧能力入口并真实写入默认时区、默认币种；
- `control_plane_start_impersonation(...)`、`control_plane_end_impersonation(...)`：跨租户 impersonation 的授权、限时 session、audit/outbox 和 start 幂等能力；
- `control_plane_replace_entitlements(...)`：授权校验、tenant CAS、整组权益替换、audit/outbox/idempotency receipt 同事务提交。

### 价格、订单、运单与报关

- `shipment_restriction_rules`：按运输、国家、渠道、客户、货型求值的限制规则；
- `order_package_snapshots`：报价和制单前的订单包裹快照；
- `accepted_quote_order_links`：精确绑定 acceptance、quote/version/option、order/waybill 和接受人；
- `waybill_lineage`、`waybill_number_history`：拆分、合并和改号证据链；
- `label_jobs`：承运商面单异步任务；
- `declaration_attachments`：报关单附件关系；
- `transaction_command_contexts`：统一关联 domain aggregate 和 foundation idempotency receipt。

### 仓储、干线、PDA 与末端配送

- 库位库存：`warehouse_location_inventory`、ledger、stocktakes、stocktake items；
- 装载关系：`load_unit_waybills`、`bill_of_lading_waybills`；
- FBA：`fba_shipment_links`、`fba_shipment_cartons`；
- 末端入库：intakes、expected waybills、scans；
- 配送任务多运单：`delivery_task_waybills`；
- PDA 媒体：`device_media_reservations`，claim 必须在 legacy media 与 reservation 中二选一；
- POD 多媒体：`pod_version_media`；
- 伙伴事件：receipts 与 append-only replay attempts；
- 末端计费：charge generations 与 generation tasks。

## 现有表的无损字段对齐

- tenant：默认时区、默认币种；user：手机号；customer：结算币种；address：标签、默认地址；
- organization：兼容 `COMPANY/DEPARTMENT/SITE/WAREHOUSE/LOCATION`；
- credit policy：decimal 金额、tier、账期天数、超额冻结、变更原因、aggregate version；
- entitlement：quota map、enabled、replacement version、aggregate version；
- channel/rate rule：运输方式、DRAFT、price type、zone、有效期、舍入、最低收费、rule/charge code；
- order/import/customs：订单类型、原子性/映射版本/验证版本/文件引用、保险金额、可选 HS/origin/weight；
- fulfillment：station、发生时间/device event、load-unit type/seal、booking carrier/ports/planned departure、主/分单、多运单配送窗口和 executor；
- PDA：subject 绑定、claimed media refs、resolution actor/reason、server version >= 1。

为旧调用方保留的原 mandatory 列在 0002 中仅做 nullable 兼容；新规范字段由业务服务逐步切换后才能停止写 legacy 字段。

## 数据完整性与安全边界

- 新 tenant 表统一 `UNIQUE(tenant_id,id)`、复合 tenant FK、ULID/version/timestamp check、tenant RLS policy 和 `FORCE ROW LEVEL SECURITY`；
- `login_throttle_buckets` 为 pre-tenant 全局 bucket：没有 `zhili_app` policy/grant，`zhili_auth` 也没有表权限，只能调用 capability function；
- `auth_lookup_refresh_token(text)` 对命中和未命中都返回一行相同形状结果，调用方再统一判定状态和过期；
- `auth_consume_login_throttle(...)` 使用原子 upsert 实现 15 分钟窗口、第五次失败封禁和成功清除；
- `control_plane_replace_entitlements(...)` 使用 DB-backed allow/deny overlay、tenant version CAS、replacement version、幂等 request hash，并在单事务写 entitlement、audit、outbox、receipt；
- 平台跨租户写 entitlement 不再伪造目标租户 creator：`created_by_user_id` 可空，平台路径用 `created_by_actor_tenant_id + created_by_actor_subject_id` 复合 FK 和互斥 shape check 保存真实 actor；
- 三个能力函数均为 `SECURITY DEFINER`、固定 `search_path`、撤销 PUBLIC execute，并仅向对应 capability role 授予执行权。

## 迁移和回滚

- Up：`packages/db/migrations/0002_b1_persistence_alignment.sql`；
- Down：`packages/db/migrations/down/0002_b1_persistence_alignment.down.sql`；
- Snapshot：`packages/db/migrations/meta/0002_snapshot.json`；
- Drizzle journal 已登记 idx 2。

Down 只删除 0002 新增函数、表、列、索引和约束，并恢复 0001 的 nullability/check；不删除 schema、role、extension、foundation 表或无关对象。若生产数据已使用 0002 才允许的值（例如 lowercase module code、新 organization type、nullable legacy 字段），回滚前必须先执行兼容性数据检查/迁移，不能通过伪造默认值强行降级。

## 后续服务实现约束

1. 各功能分支必须以 0002 schema 为唯一共享持久化契约，不再自行创建同义表或 JSON shadow state。
2. 所有 command repository 必须传递 `transaction_command_contexts` 所需的 idempotency receipt，并在同一事务提交 aggregate + audit + outbox + receipt。
3. RLS 连接每个事务必须设置 `SET LOCAL app.tenant_id`；禁止用管理员连接承载普通业务流量。
4. CAS 更新统一使用 `WHERE tenant_id=? AND id=? AND version=?`，0 rows 映射 412；跨租户引用不得降级为单列 id FK。
5. 新旧字段双写期间，以新规范字段/关系为业务事实，legacy 列仅为兼容；移除旧列需要单独 migration 和数据完成度门禁。
